## 怎么审的

只做静态审核：**没有安装、没有运行任何一个第三方包**。

- **包与版本**：npm / PyPI 上包存在、钉的版本存在、未弃用 / 未撤回（yanked）；压缩包按注册中心记录的 sha512 / sha256 校验。
- **来源**：GitHub 仓库能打开（改名的按跳转后的地址算）；条目写的仓库与包元数据里的仓库一致（同一 owner 下改名不算不一致）；仓库的 package.json / pyproject.toml 声明了同名包，或 README 提到这个包名（防冒名）。
- **许可证**：包元数据 → 包内 LICENSE 文件 → 仓库 LICENSE；商业许可、`SEE LICENSE IN` 指向非开源文本的算警告。条目没写的从元数据补上。
- **代码**：发布的压缩包下载到内存里逐文件扫（不落盘、不解压、不执行）：安装期脚本（pre/post/install、setup.py、自定义构建后端、启动即执行的 .pth）、下载即执行（curl | sh、iwr | iex、base64 解码进 shell）、读 SSH 私钥 / 浏览器 Cookie / 钱包、可疑外传端点与匿名隧道、整体外传环境变量、解码后执行、硬编码公网 IP、混淆器特征、预编译二进制、已知投毒特征（ClawHavoc 假前置安装与投放地址）、工具描述里的提示注入话术。README / PKG-INFO / METADATA / Dockerfile / CI 配置不扫（npx / uvx 不会执行它们）。命中的每一条都人工读过代码，确认无害的记在 `-manual.json` 里。
- **漏洞**：osv.dev 查钉的版本，HIGH / CRITICAL 拒绝，其余警告。
- **热度**：最近一次发布超过 2 年、或周下载量低于 20（每天不到 3 次，基本只剩镜像 / 爬虫流量）的，警告。
- **远程端点**：必须 HTTPS；端点域名与条目主页 / 仓库组织对得上，或条目引用的仓库 README 写明了这个域名；不带凭据 GET 能连上（401 / 405 也算），走代理失败时直连再试。

判定：全部无问题 → 通过（清单置 `verified: true`、`scan_verdict: allow`）；有疑点 → 警告（`warn`，保持未审核）；包 / 版本不存在、装错包、越界的下载执行行为、高危漏洞、端点不是 MCP 服务 → 拒绝（`block`，安装器永不安装）。拿不准的一律归警告。

**没覆盖到的**：运行时动态生成的工具描述与实际出网域名（要真跑起来才查得到，所以 `prompt_injection_findings` / `egress` 没写）；间接依赖（只审了包本身）；预编译二进制的行为；远程端点背后的服务端代码。

## 本轮结案口径

这一轮要求未审核条目只能有两种结果：**通过**（读过警告对应的代码 / 元数据，确认无害，在 `-manual.json` 里撤销警告并写理由，`--apply` 后 `verified: true`）或 **下架**（`scan_verdict: block`）。上面的 59 条通过、20 条拒绝即这一结论，没有保留「警告」。

- 冷门（周下载低 / 久未发布）本身不算拒绝理由，但每一条都核对了「包确实出自条目仓库」——不再只看仓库清单里有没有同名包（同名不同项目查不出来，`chess`、`memory_engine` 就是这么漏过上一轮的），而是按下面「出处核对」的办法逐条取证。
- 无许可证、厂商自有许可证只是授权问题，不影响安全，通过时写明。
- 预编译二进制：只在有构建来源证明（CI 从条目仓库构建）或能对上作者仓库时通过，二进制行为本身记入未覆盖项。

## 自研连接器改为从本仓库钉版本安装

上面删掉 uvx 跑法后，桌面端市场（只认 npx / uvx / https 跑法）不再列出这 24 条，装不上了。现在把 uvx 跑法加回来，但代码来源钉死在本仓库，不再经过 PyPI 上的包名。

### 写法

```
uvx --from git+https://gitee.com/jlzdyx/totalclaw-mcp.git@289d9c344390b7ac433a17095c85f413237fbf50#subdirectory=servers totalclaw-mcp-server <名>
```

- 来源只有 `gitee.com/jlzdyx/totalclaw-mcp`，钉 40 位提交号：不用分支名或 tag，所以不会漂。这个提交已经在 gitee master 上，它的 `servers/` 和现在的工作区一致。
- 不再查 `totalclaw-mcp-servers` 这个 PyPI 名字（抢注也影响不到）。依赖（`mcp<2`、httpx、PyYAML、anyio）仍从 PyPI 装，和其它 uvx 条目一样。
- 第一条跑法仍是本机已装的 `totalclaw-mcp-server` 命令（agent 优先用它）。uvx 是第二条，桌面端市场只认这条。

### 为什么不用 gitee 归档 zip

我们原想用归档地址 `…/repository/archive/<commit>.zip#subdirectory=servers`，这样用户不用装 git。但实测 uv 拉这个地址返回 **403**。逐段对照后找到原因：gitee 前面的防火墙（响应头 `BDWAF-Request-ID`）会拦截 User-Agent 里含 `CPython` 的请求。用 `curl -A 'x CPython'` 请求得到 403，去掉这个词就是 200。而 uv 的 User-Agent 总会带上 `"implementation":{"name":"CPython"}`，我们这边改不了。`/raw/` 以及 `/api/v5/…/zipball`、`raw`、`contents` 也都返回 403，只有 git 协议（`info/refs`）能通过。所以只能走 git，代价是用户机器上要装 git。

### 实测

测试环境：2026-11-02，macOS，uv 0.12.5。用了单独的 `UV_CACHE_DIR` / `UV_TOOL_DIR`、`GIT_CONFIG_NOSYSTEM=1`、`GIT_CONFIG_GLOBAL=/dev/null`，没用钥匙串凭据，走本机代理。只装我们自己的代码。

- 冷启动约 19 秒：拉 git 中的这一个提交（git 缓存约 3 MB）、构建、装 31 个依赖。`totalclaw-mcp-server --list` 列出 24 个服务器。
- 按 MCP stdio 协议跑 initialize 和 tools/list：web 有 2 个工具，dingtalk 有 8 个（假凭据），github 有 12 个（假凭据），都和 `tools.json` 一致。没有调用任何工具，也没有连接真实账号。缓存热了之后再次启动不到 1 秒。
- 把 PATH 里的 git 去掉后，uv 报 `Git executable not found. Ensure that Git is installed and available.`。报错清楚，但装不上。
- 把 gitee 归档里的 `servers/` 和本地 `git archive 289d9c3 servers` 逐文件比对，结果一致。

### Windows 注意

- 没装 git 的用户装不上，uv 会报上面那句英文错误。要彻底不依赖 git，得由我们自己在 PyPI 发布 `totalclaw-mcp-servers`（同时占住这个名字），再改成 `==` 写法。
- 应用自带的 `uvx.cmd` 用 `%*` 原样转发参数。git 地址里没有空格、`&`、`%`、`^`，经过 cmd 不会被拆开或改写。

- uv 和 git 都认 `HTTPS_PROXY`。gitee 在国内，一般不用代理；如果代理配置坏了，git 拉取会失败。
